# 03 Notion 與 GitHub

> 總覽：[00 總覽](00%20總覽.md)。重點只有一句：**每份內容只有一個正本。** 另一邊只放連結，或由 AI 自動產生的副本。

## 兩種配置：先用基本版，需要再加 Notion

| | 基本版（只用 GitHub＋工作台） | 完整版（再加 Notion） |
|---|---|---|
| 需要什麼 | GitHub 帳號 | GitHub ＋ Notion ＋ Claude 的 Notion 連接器 |
| 需求、回饋 | GitHub Issue（工作台的表單） | 同左（或 Notion 資料庫，二選一） |
| 提案同意 | GitHub Issue 勾選（手機可） | 同左，另外也可以在 Notion 卡片改「同意」 |
| 知識庫、素材清單 | repo 的 `docs/企劃/`（Markdown） | Notion 知識庫、素材資料庫 |
| 開發日誌 | repo 的 `docs/企劃/開發日誌.md` | Notion 開發日誌 |
| 適合 | 先跑起來、人少、不想多學工具 | 劇本、美術需要好編輯的頁面時 |

> 不管哪一版：**提案與規則書的正本都在 GitHub**，進度都看工作台。

## 哪些東西放哪邊

| 內容 | 正本在 | 另一邊 | 誰改 |
|---|---|---|---|
| 提案（說明／規則／設計／任務） | GitHub `docs/spectra/changes/` | 「提案」Issue（自動開關，放摘要＋同意勾選）；Notion 卡片（選用） | AI 寫，企劃同意 |
| 企劃同意 | `tasks.md` 的 0.1 | Issue 勾選、Notion 狀態、桌面版、對話——都會寫回 0.1 | 企劃 |
| 正式規則書 | GitHub `docs/spectra/specs/` | 工作台「規則書」分頁 | 只能透過提案改 |
| 需求、試玩回饋 | GitHub Issue（標籤「需求」「回饋」） | 處理後 AI 在 Issue 回覆結果並關閉 | 任何人寫，AI 回覆 |
| 劇情、角色、名詞、世界觀 | Notion 知識庫 或 `docs/企劃/知識庫/` | GitHub 遊戲資料檔（AI 同步產生，不要手改） | 劇本 |
| 數值表、關卡表 | 試算表（匯出給 AI） | GitHub 遊戲資料檔（AI 同步產生） | 數值／企劃 |
| 手感數值 | GitHub `web/tuning.json` | 知識庫「數值總表」放連結 | 數值 |
| 美術設計稿 | Figma | 素材清單放 Figma 連結 | 美術 |
| 素材檔（遊戲讀的圖、聲音） | GitHub `web/assets/` | 素材清單記狀態 | 美術交付，AI 放進遊戲 |
| 開發日誌 | Notion 開發日誌 或 `docs/企劃/開發日誌.md` | git 紀錄 | AI 驗收時寫 |
| 這套開發流 | GitHub `docs/flow/` | Notion／Obsidian 副本 | 程式／企劃透過提案 |
| 本機備份 | — | Obsidian（`tools/backup-obsidian.ps1`） | 自動 |

## Notion 工作區結構（完整版）

```
🎮 <遊戲名>（專案首頁：一句話、工作台連結、預覽網址、帳號表）
├─ 📘 主架構規劃書        ← 頁面：一句話、設計支柱、核心循環、核心規則（不能改的）
├─ 💡 需求池              ← 資料庫（選用；用 GitHub Issue 的話不用建）
├─ ✅ 提案確認          ← 資料庫（選用；看板檢視依「狀態」分欄）
├─ 🎮 回饋                ← 資料庫（選用；用 GitHub Issue 的話不用建）
├─ 📚 知識庫              ← 資料庫（劇情、角色、名詞、數值、世界觀、美術風格指南）
├─ 🎨 素材                ← 資料庫
├─ 📒 開發日誌            ← 資料庫
└─ 📖 開發流說明          ← docs/flow 的副本（不要在這裡改）
```

### 資料庫欄位

**💡 需求池**：標題、說明（內文）、優先（🔴 必做／🟡 想做／⚪ 之後）、提出人、狀態（新想法／討論中／已開提案／不做）、提案（關聯）

**✅ 提案確認**
| 欄位 | 類型 | 說明 |
|---|---|---|
| 名稱 | 標題 | 提案代號（例 `item-capsules`） |
| 中文標題 | 文字 | 一句話說這張在做什麼 |
| 狀態 | 選項 | 待同意／**同意**／退回／製作中／待驗收／已完成 |
| 摘要 | 內文 | 為什麼、改什麼、BREAKING、**需要企劃確認的事** |
| 任務進度 | 文字 | 例「8/8」 |
| GitHub | 網址 | 提案資料夾連結 |
| GitHub Issue | 網址 | 提案 Issue（手機勾同意用） |
| 企劃意見 | 文字 | 退回或要調整時寫這裡 |

**🎮 回饋**：標題、等級（🔴 必修／🟡 建議／🟢 很好）、輪次（數字）、版本、說明（內文，截圖直接貼）、狀態（新回饋／處理中／已處理／不處理）、處理結果（AI 回填）、提案（關聯）

**📚 知識庫**：標題、類別（劇情／角色／名詞／數值／世界觀／美術風格）、遊戲裡的位置（AI 第一次同步時填）、最後同步（日期；比「最後編輯」早＝還沒同步）

**🎨 素材**：檔名、類別（角色／場景／UI／特效／音樂／音效）、狀態（待製作／方向稿／精修中／完成／已放進遊戲）、規格、使用位置、Figma（網址）、提示詞、負責人

**📒 開發日誌**：標題、日期、版本、類型（提案驗收／修 bug／同步／自主優化）、內容（回饋 → 改了什麼 → 數據 → 驗收）、提案（關聯）

## 同步的方向與時機

| 對 AI 說 | 方向 | AI 做什麼 |
|---|---|---|
| 「看需求」 | GitHub Issue／Notion → AI | 讀「需求」Issue（與 Notion 需求池），整理後問你要開哪幾張 |
| 「把 <需求> 開成提案」 | AI → GitHub | 寫提案並推上去；**GitHub 自動開「提案」Issue**；有 Notion 的話另建卡片 |
| 「看提案」 | Issue 留言／Notion → AI | 讀企劃意見與 Notion 狀態；Notion 改「同意」的就勾 0.1；有意見的修改提案 |
| 「看回饋」 | GitHub Issue／Notion → AI | 讀未處理的「回饋」，開提案或直接修，在 Issue 回覆處理結果並關閉 |
| 「同步 <知識庫頁面>」 | Notion／`docs/企劃/` → 遊戲 | 轉成遊戲資料檔、跑測試、部署 |
| 「<名稱> 驗收通過」 | AI → GitHub（→ Notion） | 規則併回、寫開發日誌；**Issue 自動關閉**；Notion 卡改已完成 |
| 「同步開發流」 | GitHub → Notion | `docs/flow/` 覆蓋 Notion「開發流說明」 |
| 「備份」 | 兩邊 → Obsidian | 執行 `tools/backup-obsidian.ps1`，並把 Notion 頁面匯出成 Markdown |

> Notion 的頁面與資料庫 ID 記在 `docs/notion.json`（新專案第一次建 Notion 時由 AI 填寫）。

## 還沒連 Notion 連接器時：用 CSV 匯入

`docs/notion-import/` 有 6 個資料庫的 CSV（欄位照上面的表、各附一列範例）。不用等連接器，人工就能建好：

1. Notion 建一個專案頁面 → 在頁面裡輸入 `/import`（或左側「匯入」）→ 選 **CSV**
2. 依序匯入需要的 CSV，每個會變成一個資料庫；把「狀態」「等級」「類別」「優先」「類型」欄位的類型改成**選項**、「日期」改成**日期**
3. 刪掉範例列；「提案確認」加一個**看板**檢視，依「狀態」分欄
4. 之後連上連接器，對 AI 說「接上 Notion 工作區」→ AI 找到這些資料庫，把 ID 寫進 `docs/notion.json`

已經有舊資料的專案（例如原本記在 Obsidian），可以請 AI 把回饋、開發日誌、已完成的提案轉成同樣格式的 CSV 一起匯入。

## 為什麼這樣分

- **全部 Notion**：AI 不能在 Notion 裡跑測試、部署，規則書和程式會對不上
- **全部 GitHub 檔案**：劇本、美術要學 Markdown 和 git，門檻太高
- 所以：**提案、規則、程式在 GitHub；人的輸入用 Issue 表單（手機可）或 Notion；所有人看同一個工作台**
