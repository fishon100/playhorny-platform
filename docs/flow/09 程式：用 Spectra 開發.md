# 09 程式：用 Spectra 開發

> 給程式看的。企劃那條線（企劃提案 → 企劃同意 → 測試過就上線）不用等程式；程式這條線處理**玩家看不到的改動**，並把關 AI 寫的程式。

## 兩條線

| | 企劃提案 | 技術提案 |
|---|---|---|
| 是什麼 | 玩法、畫面、數值、文字；會改規則書 | 重構、效能、工具、測試、建置；**不改規則書** |
| 提案第二行 | `> 類型：企劃` | `> 類型：技術` |
| 誰同意（任務 0.1） | 企劃 | **程式** |
| 怎麼上線 | 測試全過就上線，企劃試玩驗收 | 分支 `tech/<名稱>` → PR → 自動測試 → **程式審查合併** → 部署 |
| 管理台 | 企劃的「我的待辦」 | 程式的「我的待辦」（紫色「技術」標籤） |

拿不準是哪一種就當企劃提案。會新增或修改規則書的一律是企劃提案。

## 第一次準備（約 15 分鐘）

1. 安裝：Git、Node.js 22 以上、GitHub CLI（`gh auth login`）、Claude Code
2. Spectra：`npm install -g @kaochenlong/spxa`；想一次看全部提案的話裝 **Spectra 桌面版**，把專案資料夾加進去
3. 下載專案並初始化：

```bash
gh repo clone <帳號>/<專案>
```

```bash
spxa init --tools claude
```

4. 在 Claude Code 打開專案資料夾，說「**檢查環境**」，缺什麼 AI 會告訴你
5. 管理台右上角「我的角色」選 **程式**：首頁只會出現等你同意的技術提案、等你審查的 PR、失敗的自動測試

## 每天的流程

**你想改東西（重構、加快、換工具）**
1. 對 AI 說「開技術提案：<要改什麼、為什麼>」→ AI 寫提案、推上去，GitHub 自動開「技術提案：…」討論串
2. 你自己就是程式，可以直接說「同意 <名稱>」（AI 註明「程式於對話中同意」）
3. 說「做 <名稱>」→ AI 在分支 `tech/<名稱>` 上先寫測試、再改、跑全部測試，最後開 PR 並停下來
4. 你在 GitHub 審查 PR（清單見下面）：有意見就留「Request changes」，然後對 AI 說「PR #N 照意見改」；沒問題就按 **Merge**
5. 對 AI 說「PR #N 合併了」→ AI 拉下最新版、部署、通知；確認沒問題後說「<名稱> 驗收通過」歸檔

**AI 或企劃提的技術提案**
- 管理台／工作台「我的待辦」會出現，或手機收到 GitHub 通知 → 打開討論串讀「為什麼、改什麼、需要程式確認的事」→ 勾 **☐ 程式同意**（或在管理台按同意）

**企劃提案**：你不用同意，但可以在討論串留技術意見；AI 做完會直接上線。想多看一眼的話，用 Spectra 桌面版看 design.md。

## PR 審查清單

- [ ] **測試先行**：有新的或改過的測試，而且不是只為了讓它過而改測試
- [ ] **沒有改到規則書**（`docs/spectra/specs/`）；改到的話應該是企劃提案
- [ ] **自動測試是綠的**（PR 下方的 checks）
- [ ] 做法夠簡單、之後好改；沒有多出用不到的東西
- [ ] 沒有把密碼、金鑰、登入碼寫進程式或設定檔
- [ ] 效能類的改動附了量測數字（改前／改後）

## 自動測試在哪裡跑

- **你的電腦**：`node --test`（有網頁版的專案另有瀏覽器測試，部署前會自動跑）
- **GitHub**：每次推上去、每個 PR 都會跑；沒過會在 PR 上顯示紅叉，部署也會被擋下，手機會收到通知

## 還沒有程式的團隊

企劃可以代為同意技術提案（註明「企劃代程式同意」），PR 確認測試是綠的就可以合併。之後有程式加入，這條線不用改，換人按就好。
