# 07 對 AI 說的話

> 總覽：[00 總覽](00%20總覽.md)。在 Claude Code（電腦上，或手機 Claude App 的 Remote Control）直接打這些話就好，AI 讀 `CLAUDE.md` 就知道要做什麼。
> 最常用的一輪：說想要什麼（或「看需求」）→ AI 在對話中跳出確認選項 → 選「同意」→ AI 做到上線 → 試玩後說「X 驗收通過」。不用另外說「做 X」，也不用去管理台按同意。
> 不在電腦前：用手機 Claude App 的 Remote Control 下同樣的指令。管理台、工作台上的「對 AI 說…」按鈕會幫你複製這些話（管理台本身不會叫 AI）。

## 日常

| 說 | AI 做什麼 |
|---|---|
| 同步 | 把你在管理台做過的事接手：在管理台同意的提案（問你要不要開始做）、提案討論串的新留言、新的回饋與需求、改過的企劃文件（同步回 Obsidian）、關卡編輯器還沒套用的修改；用選項問你先處理哪些 |
| 現在做到哪 | 看工作台資料與 `spxa list`：等誰、做到哪、有沒有部署失敗 |
| 看需求 | 讀「需求」Issue（與 Notion 需求池），整理後問你要開哪幾張提案 |
| 討論 <需求> | `/spectra-discuss`：比較做法、問清楚，不改程式 |
| 把 <需求> 開成提案 | `/spectra-propose`：寫提案、推上去（自動開提案 Issue，工作台出現「等你同意」） |
| 同意 <名稱> | 勾提案任務 0.1，註明「企劃於對話中同意」 |
| 看提案 | 讀提案 Issue 的留言、Notion 狀態；Notion 改「同意」的勾 0.1，有意見的修改提案 |
| 做 <名稱> | 確認 0.1 已勾 → `/spectra-apply`：先寫測試、再實作、跑測試、部署、通知 |
| <名稱> 改成 … | `/spectra-ingest`：把新要求寫回提案，取消 0.1，請你再同意一次 |
| 看回饋 | 讀未處理的「回饋」Issue（與 Notion），開提案或直接修，回覆處理結果 |
| <名稱> 驗收通過（舊說法「結案」也可以） | 先看試玩清單：全部勾完才繼續（沒勾完或有不通過的會先問你）→ `/spectra-verify` → `/spectra-archive`：規則併回、寫開發日誌；提案與試玩清單的討論串自動關閉 |
| <名稱> 第 N 項試過沒問題 | 代你勾試玩清單那一項，註明「企劃於對話中確認」 |
| 素材 <檔名> 交件了 | 找到上傳的檔案，素材清單那一列改「待確認」、填交件路徑 |
| 素材 <檔名> 採用 ／ 素材 <檔名> 退回：<意見> | 素材清單改「已採用」或「退回」＋意見；採用的在下次「同步」放進遊戲，改「已放進遊戲」 |
| 把主架構規劃書的核心規則抄進 config | 把一句話、設計支柱、核心循環、核心規則抄進 `docs/spectra/config.yaml` 的 context；之後每張提案都要寫服務哪個支柱，碰到核心規則會警告。規劃書的核心規則改了也說一次 |
| 修 <問題> | `/spectra-debug`：先重現、找原因；不改規則就直接修 |

**程式用**（技術提案：程式同意、做完開 PR 給程式審查，見 [09](09%20程式：用%20Spectra%20開發.md)）

| 說 | AI 做什麼 |
|---|---|
| 開技術提案：<要改什麼> | `/spectra-propose`，第二行寫「> 類型：技術」；Issue 標題「技術提案：…」，等程式同意 |
| 同意 <名稱>（程式說） | 勾 0.1，註明「程式於對話中同意，日期」 |
| 做 <技術提案名稱> | 在分支 `tech/<名稱>` 做：先寫測試、實作、跑全部測試 → 開 PR，停下來等程式審查（不自己合併） |
| PR #N 照意見改 | 讀 PR 審查意見，改完推到同一個分支，在 PR 回覆改了什麼 |
| PR #N 合併了 | `git pull` → 部署、通知 → 問要不要驗收歸檔 |

## 內容同步

| 說 | AI 做什麼 |
|---|---|
| 同步 <知識庫頁面> | Notion 頁面（或 `docs/企劃/`）→ 遊戲資料檔，跑測試、部署 |
| 同步 <表名> | 試算表（xlsx／csv）→ 遊戲資料檔，先列出改了哪些給你確認 |
| 套用調參 | 調參面板的數值寫回 `web/tuning.json` 與數值總表 |
| 換上 <素材> | 把素材接進遊戲，素材清單狀態改「已放進遊戲」 |
| 出 <東西> 方向稿 | 依美術風格指南寫提示詞、產出方向稿 |

## 環境與維護

| 說 | AI 做什麼 |
|---|---|
| 檢查環境 | `node tools/doctor.mjs`：Node、git、gh 登入與權限、Spectra、測試；缺什麼告訴你怎麼補（換電腦先說這句） |
| 檢查連接器 | 列出 Notion／Figma／Drive／GitHub 連線狀態，並確認帳號正確 |
| 建 Notion 工作區／接上 Notion 工作區 | 建立或找到 Notion 頁面與資料庫，ID 寫進 `docs/notion.json` |
| 更新工作台 | 手動觸發 GitHub Actions 的 `workbench`（平常推上去或 Issue 有變動就會自動更新） |
| 量一下 <關卡> 難度 | 擬人玩家跑 30～40 局，回報掉命數、時間 |
| 同步開發流 | `docs/flow/` → Notion「開發流說明」 |
| 備份 | 執行 `tools/backup-obsidian.ps1`，把 repo 文件與 Notion 匯出到本機 Obsidian |
| 部署 | 推上 GitHub，Actions 跑測試並部署，手機收到通知 |

## 進階

- `/goal <完成條件>`：讓 AI 一路做到條件達成，不中途問問題。例：`/goal 做完 item-capsules，測試全過並部署`
- 一次交辦多件：「看回饋，能直接修的修掉，要開提案的先開好等我同意」
