# 遊戲開發流｜總覽

> 目標：**讓 3～5 個人的小團隊，靠 AI 完成一整個遊戲專案。**
> 做法：人決定「要什麼」和「對不對」，AI 負責「做出來」和「證明做對了」。
> 骨幹：[Spectra](https://github.com/kaochenlong/spectra-app)（規格驅動開發 SDD）＋ 自動測試（測試驅動開發 TDD）。

## 一張圖看懂

```
            人（任何裝置：手機、平板、電腦）                     AI（在一台電腦上的 Claude Code）
 ┌────────────────────────────────────────────┐          ┌──────────────────────────────────┐
 │ 💻 管理台：多專案、流程樹、內容庫、素材庫      │          │ 讀需求／回饋 → 寫提案             │
 │ 🧭 工作台（手機）：等我處理、同意、寫回饋      │          │ 同意後：先寫測試 → 實作 → 測試全過   │
 │ 💬 GitHub Issue：提需求、寫回饋、☐ 企劃同意   │ ◀──────▶ │ 推上 GitHub → 自動部署 → 手機通知    │
 │ 📒 Notion（選用）：知識庫、素材、日誌          │   同步   │ 驗收：規則併回規則書、寫日誌         │
 │ 🖥 Spectra 桌面版（選用）：看提案細節、勾同意 │          │                                  │
 └────────────────────────────────────────────┘          └──────────────────────────────────┘
                    ▲ GitHub Actions 自動：同意 → 任務 0.1 打勾、開／關提案 Issue、更新工作台
                    └──── Obsidian：本機備份 ────┘
```

## 四條原則

1. **需求寫成文件，不靠聊天紀錄。** 聊天會消失（換帳號、換人、換 AI），文件不會。
2. **一個內容只有一個正本。** 提案與規則在 GitHub；人寫的需求、回饋在 GitHub Issue（或 Notion）；其他地方只放連結或自動產生的副本。→ [03 Notion 與 GitHub](03%20Notion%20與%20GitHub.md)
3. **改規則一定開提案，同意才動工。** 企劃提案由企劃同意、技術提案（重構、效能、工具）由程式同意並經程式審查 PR。同意可以在工作台／GitHub、Notion、Spectra 桌面版、或直接跟 AI 說，最後都記在提案任務 0.1。→ [01 一輪開發](01%20一輪開發.md)
4. **沒有測試證明，就不算做完。** 能自動判斷對錯的交給測試；「好不好玩」交給人在手機上試玩。→ [04 品質把關](04%20品質把關.md)

## 為什麼這樣能少人做完

| 傳統做法要人做的事 | 這套流程 |
|---|---|
| 程式照規格寫程式 | AI 照提案的任務寫，`/spectra-apply` 可以平行做 |
| QA 每次手動測一遍 | 自動測試每次部署前跑，壞了就擋下 |
| PM 追進度、寫週報 | 工作台即時顯示：等誰、做到哪、有沒有上線成功；開發日誌由 AI 驗收時寫 |
| 開會對齊需求 | 提案把「為什麼、改什麼、需要確認的事」寫清楚，企劃在手機勾同意就是對齊 |
| 交接時翻聊天紀錄 | 規則書＋提案歷史＋開發日誌＋工作台，新的人（或新的 AI）讀了就能接手 |
