## 💻 管理台

網址：https://fishon100.github.io/game-dev-flow-template/console/ （左上角 📁 切換專案；網址加 `?repo=<帳號>/<專案>` 直接開某個專案）

介面像 Spectra 桌面版：**左側選單、中間清單或樹狀圖、右側明細**。

| 選單 | 看什麼 |
|---|---|
| 🏠 總覽 | 摘要列（待同意 → 製作中 → 待驗收 → 已完成，各有幾張）、**我的待辦**（依角色）、進行中提案、最近上線 |
| 流程圖 | **泳道圖**：上方是標準流程（需求 → 寫提案 → 企劃同意 → 製作 → 調整？→ 試玩驗收 → 規則併回 → 完成，含「先討論」「改提案」分支）；下方每張進行中的提案一條泳道，綠色勾＝走過、亮色格子＝目前這一步（點開看明細）。右上角可切換「結構樹」看每份文件與任務 |
| 📋 提案 | 所有提案的表格；明細有**進度鏈**（說明 → 規則 → 設計 → 任務 → 同意 → 製作 → 驗收）、為什麼、改什麼、需要確認的事、任務清單、同意按鈕、「對 AI 說」指令 |
| 📜 規則書 | 功能 → 規則（中文）→ 情境（每個情境對應一個自動測試） |
| 📖 劇本／🧑‍🎨 角色／🌏 世界觀／🏷 名詞／📊 數值／📘 規劃書／🗂 紀錄 | 企劃內容，直接在管理台閱讀（表格、圖片都會顯示）；每份右上角「編輯」、分類頁「新文件」 |
| 🎨 素材庫 | 素材進度表（依狀態、類別篩選）、圖片牆（點開看大圖、下載）、聲音、素材清單與風格指南 |
| 💬 回饋與需求 | 同工作台；每則有「對 AI 說：把 #N 開成提案」 |
| 🚀 上線紀錄 | 同工作台，另有等程式審查的 PR |
| 專案工具 | 這個專案自己的工具（外掛），例如彈珠的「關卡編輯器」；見下方「專案工具（外掛）」 |
| 專案目錄 | 所有專案的卡片（待同意幾張、進行中、已完成）；也可以從上方的專案下拉選單直接切換 |

### 專案工具（外掛）

基本框架（流程、提案、規則書、內容庫、素材庫、回饋）是**所有專案共用**的。每個遊戲常需要自己的工具——彈珠的「關卡編輯器」、RPG 的「對話編輯器」、卡牌遊戲的「卡片數值試算」——這些是**專案工具**，只出現在那個專案的管理台左側「專案工具」與工作台首頁。

在專案的 `workbench.config.json` 加 `tools`：
```json
"tools": [
  { "label": "關卡編輯器", "url": "https://…/editor.html", "icon": "wrench", "desc": "畫磚塊與台面，複製回關卡表" }
]
```
- 工具本身（網頁）用提案開發，放在專案的 `web/` 底下，跟遊戲一起部署
- `links` 只放「試玩」這類每個專案都有的入口；專案特有的東西一律放 `tools`
- icon 可用：wrench、table、chart、image、gamepad、code、flask、book、users、globe、tag、play、sparkles

### 👤 我的待辦（依角色）

第一次打開會問「你主要負責什麼」（企劃、美術、程式、劇本／數值、全部），之後在首頁「需要處理」右上角可以換。只存在這台瀏覽器。

| 角色 | 首頁列出 |
|---|---|
| 企劃 | 等你同意的提案、待驗收（請試玩）、還沒處理的回饋與需求、標【企劃】的任務 |
| 美術 | 標【美術】的任務、素材清單裡「待製作／修改」的數量 |
| 程式 | 等審查的 PR、失敗的測試、企劃已同意但還沒開始的提案（對 AI 說「做 xxx」）、標【程式】的任務 |
| 劇本／數值 | 標【劇本】【數值】的任務 |

另外，指派給你（GitHub 的 Assignees）或貼了你角色標籤（例如「美術」）的回饋與需求，也會出現在你的待辦。
**任務怎麼標角色**：AI 寫提案時，需要人做的任務會在開頭標【美術】【劇本】等（規定在 `docs/spectra/config.yaml`）。

### 🔑 不登入也能操作；登入碼是選用的

**不登入**：按「同意」「寫回饋」「提需求」「編輯」「新文件」「上傳素材」時，管理台會打開**已經填好的 GitHub 網頁**，在那裡按一下送出就完成。只要瀏覽器有登入 github.com（手機用 GitHub App 或瀏覽器）就好，不用任何設定。

| 動作 | 不登入（打開 GitHub） | 有登入碼（直接在管理台） |
|---|---|---|
| 👍 同意提案 | 打開提案討論串，勾 ☐ 企劃同意 | 直接同意 |
| 💬 留言／提問 | 打開討論串留言 | 直接送出 |
| 🎮 寫回饋、💡 提需求 | 管理台填好 → 打開預先填好的 GitHub 表單 → 按 Create（截圖拖進去） | 直接送出，截圖自動上傳到 `docs/企劃/圖/回饋/` |
| ✏️ 編輯文件、＋ 新文件 | 打開 GitHub 編輯頁 → Commit changes | 管理台編輯器（可預覽），存到 GitHub |
| ＋ 上傳素材 | 打開 GitHub 上傳頁，把檔案拖進去 | 直接上傳到 `docs/企劃/圖/`，同名自動改名 |

**設定登入碼**（想留在管理台裡操作時；每台電腦／瀏覽器一次）：右上角「登入」→ 展開「設定登入碼」
1. 按「產生登入碼」→ GitHub 會打開已經勾好權限的頁面（Contents、Issues 讀寫，90 天到期）→「Repository access」選要管理的專案 → **Generate token** → 複製 `github_pat_…`
2. 貼回管理台按「登入」。共用電腦請取消「記住這台電腦」，用完按頭像 → 登出

**為什麼不能像一般網站按「用 GitHub 登入」**：管理台是放在 GitHub Pages 的純網頁，沒有自己的伺服器；GitHub 的登入按鈕（OAuth）最後一步需要一把只能放在伺服器上的密鑰。要做成一鍵登入，需要另外架一個小伺服器（例如免費的 Cloudflare Worker）＋註冊 GitHub OAuth App——之後要做再說。

**正本在 Obsidian 的專案**（例如噴漆闖關）：在管理台或 GitHub 改的內容，下次「同步企劃文件」會**寫回 Obsidian**；兩邊都改過同一份會擋下來請人決定，不會互相蓋掉。
**權限**：專案擁有者或組織成員用上面的登入碼；**協作者**（專案在別人帳號底下）要改用「傳統登入碼」（勾 `repo`），連結在登入畫面裡。建議團隊把專案放到 GitHub 組織底下，權限比較好管。
**安全**：登入碼只存在你的瀏覽器、只會送到 GitHub；不要貼給別人或貼在聊天裡；過期了再產生一個就好。

### 🔁 管理台 ⇄ 對話：兩邊都能做事

| 你在哪 | 怎麼做 | 另一邊怎麼知道 |
|---|---|---|
| **管理台**（自己動手） | 同意、留言、寫回饋、編輯文件、上傳素材、關卡編輯器送出 | 回到對話說「**同步**」，AI 列出你在管理台做的事、問你要先處理哪些，選了就直接做 |
| **對話**（叫 AI 代做） | 「同意 X」「在 X 留言…」「寫一則回饋…」「把角色卡的…改成…」「第 3 關改成…」 | AI 推上 GitHub，管理台約 1 分鐘更新；留言和修改紀錄會寫「企劃於對話中要求」 |

### 🤖 AI 怎麼配合管理台：管理台不叫 AI，AI 協助管理台

團隊決定：**管理台、工作台不會自己叫 AI 開工**，也不設定 GitHub 上的自動 AI。分工是：

| | 誰 | 在哪裡 |
|---|---|---|
| 看進度、做決定（同意、回饋、編輯、上傳） | 人 | 管理台／工作台／GitHub |
| 叫 AI 做事（寫提案、製作、改提案、驗收） | 人下指令 | **Claude**（電腦，或手機 Claude App 的 Remote Control） |
| 讓管理台反映真實進度 | AI | 做完就推上 GitHub，管理台約 1 分鐘更新 |

- 需要 AI 的地方，管理台會有「**對 AI 說「做 xxx」**」按鈕：按一下複製這句話，貼到 Claude 就好
- AI 的責任（寫在 `CLAUDE.md`「AI 協助管理台」）：提案照格式寫、需要人做的任務標角色、每完成一項就勾任務、處理完回饋就在 Issue 回覆並關閉、做完一定推上 GitHub——這些都會直接變成管理台上的進度條、待辦、未處理數
- 管理台上的數字不對：對 AI 說「**更新工作台**」，AI 會檢查同步並重跑

**內容從哪裡來**：每個專案 `workbench.config.json` 的 `content_dirs`（預設 `docs/企劃/`）。資料夾名稱決定分類：`劇情`→劇本、`角色`→角色、`世界`→世界觀、`名詞`→名詞、`數值`→數值、`規劃書`→規劃書、`媒體庫／美術／音樂`→素材庫；名稱含「素材」的 CSV 會變成素材進度表。
**新增專案到目錄**：把 `{ "repo": "帳號/專案", "name": "名稱" }` 加進範本的 `web/console/projects.json`（全隊看得到），或在管理台「專案目錄」輸入（只存在自己的瀏覽器）。

## 🧭 工作台

網址：`https://<帳號>.github.io/<專案>/workbench/`
（看別的專案：在網址後面加 `?repo=<帳號>/<專案>`，例：[噴漆闖關的工作台](https://fishon100.github.io/game-dev-flow-template/workbench/?repo=fishon100/pinball-sling)）

**手機加到主畫面**：Safari 按「分享 → 加入主畫面」；Chrome 按「⋮ → 加到主畫面」。之後就像 App 一樣點開。

| 分頁 | 看什麼 | 可以做什麼 |
|---|---|---|
| 🏠 首頁 | **我的待辦**（依角色，和管理台共用同一個設定）、統計、進行中提案、最近上線 | 選角色、試玩、寫回饋、提需求、去同意 |
| 📋 提案 | 每張提案的狀態、為什麼、需要確認的事、進度條、下一步；已完成的時間線 | 看內容並同意、對 AI 說「做 xxx」、看完整提案、討論 |
| 💬 回饋與需求 | 還沒處理的回饋、需求；已處理的 | 寫回饋、提需求、對 AI 說「把 #N 開成提案」 |
| 📘 規則書 | 遊戲現在的規則（每份幾條） | 點進去看全文 |
| 🚀 上線紀錄 | 等審查的 PR、自動測試與部署成功／失敗、最近的改動 | 點失敗的看原因 |
| ❓ 怎麼用 | 操作說明、狀態意思 | — |

**資料多新？** 每次推上 GitHub、有人勾同意或寫 Issue，GitHub Actions 約 1 分鐘內更新；另外每小時自動更新一次。右上角會寫「更新於 X 分鐘前」，按 ⟳ 重新整理。沒有網路時會顯示上次的資料。

手機上的「對 AI 說」：會**複製一句指令**，貼到 Claude App（Remote Control 連到電腦上的 Claude）就好。

### 它是怎麼運作的（給程式）
```
推上 main／Issue 或 PR 有變動／部署跑完／每小時
   └─ GitHub Actions「workbench」（.github/workflows/workbench.yml → tools/workbench/sync.mjs）
        ├─ Issue 勾了「企劃同意」→ tasks.md 0.1 打勾並 commit
        ├─ 新的提案 → 開「提案」Issue；已完成 → 關 Issue
        └─ 產生 data.json → 推到 workbench-data 分支
工作台（web/workbench/index.html，靜態網頁）讀 raw.githubusercontent.com/<repo>/workbench-data/data.json
```
- 工作台只讀公開資料，不需要登入；所有「動作」都是連到 GitHub 的頁面（用你自己的 GitHub 帳號）
- data.json 另外有 `pulls`（開著的 PR，給程式審查）
- 私人 repo：工作台讀不到資料（要另外處理權杖），建議用公開 repo，或只在電腦上看 Spectra 桌面版

## ✅ 在手機同意提案

1. 工作台首頁「📝 xxx 等你同意」→ **看內容並同意**（或 GitHub App 的通知）
2. 讀 **為什麼／改什麼／❓需要企劃確認的事**
3. 勾 **☐ 企劃同意**；有意見就留言（不要勾）
4. 約 1 分鐘後 Issue 會出現「✅ 已記錄企劃同意」，工作台變成「已同意」

> 第一次勾要登入 GitHub，且帳號要對 repo 有權限（Triage 以上）。

## 📱 不在電腦前，怎麼叫 AI 做事

| 想做的事 | 用什麼 | 電腦要開著嗎 |
|---|---|---|
| 看進度、同意、寫回饋、提需求 | 工作台＋GitHub App | ❌ 不用 |
| 叫 AI 做事（寫提案、製作、驗收） | **Claude 手機 App 的 Remote Control**：連到電腦上開著的 Claude Code，像坐在電腦前一樣下指令、看它做到哪 | ✅ 要，且不能睡眠 |
| 試玩最新版 | 部署通知（ntfy）或工作台「▶ 試玩」 | ❌ 不用 |
| 知道 AI 做完了 | ntfy 推播（部署成功／失敗）、GitHub App 通知（Issue 回覆） | ❌ 不用 |

**Remote Control 怎麼開**：在電腦的 Claude Code 開啟 Remote Control（桌面版 Code 分頁的 Remote Control 設定），手機 Claude App 就會看到這個工作階段。長時間任務建議搭配 `/goal`，AI 會一路做到完成。

## 💻 換裝置

| 換什麼 | 影響 | 要做什麼 |
|---|---|---|
| 企劃換手機／電腦 | 無 | 打開工作台網址、登入 GitHub 就好 |
| AI 那台電腦換掉 | 要重新準備環境 | 照 [05 工具與帳號](05%20工具與帳號.md)「換一台電腦」，最後說「檢查環境」 |
| Spectra 桌面版只裝在某台電腦 | 只有那台能用桌面版 | 其他裝置用工作台＋GitHub 同意，效果一樣 |
| 換 Claude 帳號 | 連接器要重連 | 照 05「換 Claude 帳號／換人接手」 |
